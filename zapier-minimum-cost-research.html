🏗️ 当前生产架构（已最优）

GitHub Issue（触发器，0 task）
  → Filter by Zapier（0 task，验证所有者/非PR/开放）
  → Code by Zapier（1 task，dispatch GitHub Actions）
      → GitHub Actions: luna-autonomous.yml
          → prepare-full-audit.mjs（分批，72 批 @950K）
          → 逐批 sdk.createActionRun(app=AICLIAPI@4.0.28, action=get_completion)
              authentication_id='0'（Zapier 托管）, model_id=openai/gpt-5.6-luna
          → validateAnswer（覆盖校验）
          → 汇总 → 中文报告 → 草稿 PR（不自动合并）

设计要点

  • 一次 Issue 仅 dispatch 一次：Code 步骤只触发 Actions，所有分批循环在 Actions 内完成，避免逐批触发 Zap（每批 1 task）
  • SDK Beta 免费：72 次模型调用经 SDK，Beta 期间 0 task
  • Luna = Standard 1x：最便宜的 Zapier 托管模型；上下文 1.05M
  • 免费逻辑步骤：Filter 免费；去重、装箱、覆盖校验、聚合均在 Actions 的 Node.js 中完成（不占 Zapier task）
  • 安全护栏：max_tasks 预算（≤74）、usageGuard 检测异常增长、请求状态不明禁止重发

📉 降本策略总结

  1. 最大化 SDK Beta 免费期：当前是最低成本窗口——每 Issue 仅 1 task。Beta 结束前官方会通知，届时再评估迁移。
  2. 用 Luna（Standard 1x）做全量扫描：Luna 是 Zapier 托管最便宜模型（1x），上下文 1.05M。Premium 模型（5x）仅用于关键模块复核。
  3. 保持"一次 Code dispatch"设计：所有分批循环在 GitHub Actions 内完成，绝不逐批触发 Zap 步骤。
  4. 用免费内置工具承担逻辑：Filter（0 task）验证 Issue；去重、装箱、覆盖校验在 Actions 的 Node.js 中完成。
  5. 增大单批可靠容量：从 484K 提升到 950K 可将批次数从 128 降至 72，Beta 后 tasks 从 129 降至 73。需修复 .md 文件类型问题（改用 .txt）。
  6. BYOK 仅作备选：AI by Zapier BYOK（1x）需用户自备 provider key。用户明确"只用 Zapier 模型"，故不作主方案。

⚠️ 已知问题与下一步

本轮测试遇到的问题

  • usageGuard / requireFreeSdk 导致模型调用前停止：Run #36039575229 在分批准备完成后、首次模型调用前失败（modelRequests=0）。可能原因：requireFreeSdk() 的定价页正则检查脆弱，或 usageGuard 检测到 usage read 自身引起的计数变化。需查看完整错误日志定位。
  • 950K .md 批次未通过模型验证：历史数据显示 .md 在 920K 时报 "file type not supported"。当前 prepare-full-audit.mjs 目标 950K 生成 .md 附件，需验证是否能通过模型。建议改用 .txt 格式或降低目标至 484K。
  • Premium 模型未接入：当前 AICLIAPI 集成和 checkConfig 硬编码 Luna。如需 GPT-5.6 Sol / Fable 5，需修改集成配置和校验逻辑。

建议的下一步验证

  1. 修复 requireFreeSdk / usageGuard 问题，确保模型调用能正常发起
  2. 用 1–2 个 484K .txt 批次实测模型调用成功（Beta 期间 0 task）
  3. 尝试 950K .txt 批次，确定可靠最大容量
