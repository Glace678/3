🏆 核心结论

全仓审核最低消耗（确定数字）

  • SDK Beta 期间：1 task / Issue（Code dispatch 一次，72 批模型调用经 SDK 免费）
  • Beta 后（484K 可靠容量）：129 tasks / Issue（1 Code + 128 SDK × 1）
  • Beta 后（950K 若可行）：73 tasks / Issue
  • Agent 路径：~5-10 activities / run，Free 400/月 ≈ 40-80 次全仓

薅额度 TOP 5

  1. SDK Open Beta 免费——当前最大羊毛，9000+ app 全免费
  2. 0-task 白名单：Filter/Formatter/Paths/Delay/Looping/Storage/Tables/Digest/Manager 全免费
  3. AI 步骤降档：默认 Premium(5x) → Standard(1x)，立省 80%
  4. Filter 放最前：挡掉无关事件，后续 action 根本不跑
  5. Code 合并多步：3-4 个 action → 1 个 Code step = 1 task
⚠️ 红线：注册多个免费账号刷额度违反 Zapier Acceptable Use Policy（"create multiple accounts to circumvent limitations"），会被批量封禁。Test step 是 live 的，成功就扣 task。

B. Agents 平台深度解析（agents.zapier.com）

B1. Builder 四块详解

1) Trigger（触发器）

  • On Demand：手动点 Run 或聊天发消息才运行
  • Schedule by Zapier：按固定间隔自动运行
  • Trigger via Zap workflows & MCP：由另一个 Zap 或 MCP 调用触发
  • App trigger：直接选某个 app 的事件作为触发

是否耗 activity：是——"An agent uses a trigger" = 1 activity。

2) Instructions to follow（指令）

自然语言 prompt 框，支持用 / 插入工具和知识源 pill。写指令本身不耗 activity，只有实际运行时执行的动作才耗。

3) Tools（工具）

  • Default Tools: Visit Site & Web Search（所有 agent 自带）
    • Visit site：访问指定 URL 抓公开页面内容。不能登录需要鉴权的站点（官方明确："cannot log in to websites"）
    • Web search：按关键词做网页搜索
    • 每次实际调用 = 1 activity
  • + Add Tool（9,000+ apps）：从 Zapier 全 app 库挑 action 作为工具。每跑一次 action = 1 activity。两个 tab：Find data（搜索/读）、Take action（写/改）
  • Call an agent：子任务委托给另一个 agent。子 agent 运行时自身产生的 action 照常计 activity

4) Knowledge sources（知识源）

  • 上传文件：CSV/PDF/ODT/PPTX/DOCX/TXT，单文件 ≤100MB
  • 从 app 添加：Zapier Tables、Google Docs 等
  • 是否耗 activity：是——"agent answers a question using a knowledge source" = 1 activity

5) Agent Preview（预览/聊天面板）

右侧实时聊天/测试面板。Free 计划：测试计入 activity 配额；Paid 计划：测试不计。

B2. 计量规则（activities）——5 个关键问题

① 一个 activity 的精确定义

官方原文："An activity is any billable action that your agent takes." 以下每发生一次 = 1 activity：

  1. agent 使用一次 trigger（触发）
  2. agent 用知识源回答一次问题
  3. agent 跑一次 action（工具调用）
  4. agent 做一次网页浏览/抓取
  5. agent 做一次网页搜索
  6. 通过 Chrome Extension 给 agent 发一条消息
关键结论：activity 不是「一条聊天消息」，也不是「一次完整任务」，而是「一次可计费动作」。多轮对话/一次运行 = 多个 activity。官方示例：每天跑一次、只命中 1 封邮件 = 4 activities（查邮箱+总结+加 Trello+发 Slack）；命中 2 封 = 7 activities。

② 模型选择 & 高级模型是否多耗 activity

  • 独立 Agents Builder：官方文档没有暴露模型选择面板；agent 使用 Zapier 默认模型。GPT-5.6 Sol / Claude Fable 5 在独立 Agents Builder 里未确认可选
  • 迁移后（AI by Zapier 步骤）：才有模型层级选择，按 task 倍数计费（Standard 1x / Advanced 3x / Premium 5x / BYOK 1x）
  • 独立 Agents 的 activity 是否因选高级模型而多扣：官方 activity 文档里没有按模型加价的条款 → 未确认（activity 计量与模型解耦）

③ Professional trial 对 Agent 是否叠加更多 activities

14 天 Professional 试用针对的是 Zap tasks（750 tasks/mo）。Agents 是独立 add-on：Agents Free = 400 activities/mo；Agents Pro = $33.33/月（年付 $400/年）= 1,500 activities/mo。官方未说明 trial 会给独立 Agents 叠加额外 activities → 未确认。按现有文档，trial 期间 Agents 仍按 Free（400 activities，且测试计配额）口径走。

④ "New pod" 是什么

Pod = agent 的分组空间/文件夹，不是计费单位，也不是新环境。用于把工作流相近的 agent 归到一起，方便统一查看 pod activity。一个 agent 可同时属于多个 pod。

⑤ "Agents 正迁移到 AI by Zapier" 的影响

  • 迁移方向：agents.zapier.com 独立产品 → AI by Zapier（Zap 编辑器内的一个步骤）
  • 时间线：2026-07-15 AI by Zapier GA；2026-07-15~08-15 Enterprise trial 客户迁移窗口；2026-08-15 Enterprise trial 到期
  • 计费变化：迁移前按 activities（400/1500…）；迁移后并入 Zap 的 task-based 计费，AI 步骤按模型层级 1×/3×/5×；单次 run 超 75 tasks 自动暂停待审
  • 功能变化：每个 agent 自动转成一个 Zap（原生 trigger + 单个 AI by Zapier 步骤）。新增：模型层级选择、per-tool 审批、结构化输入输出、Zap history 全可观测
  • 旧版还能用多久：Free/Pro 账号的旧版独立 Agents 最终下线日期未确认（当前仍可访问，My agents 列表顶部出现 "Migrate your Zap" 横幅）

C3. 完成"全仓代码分析"最省的组合

残酷事实：Zapier GitHub app 的已确认 action 里没有「读仓库文件内容」「触发 GitHub Actions workflow」「建 PR」这类能真正拉取全仓代码的动作；agent 的默认 Visit Site 又不能登录、不能访问私有 repo。因此「全仓代码分析」靠 Zapier 原生 GitHub action 链无法直接完成。

在已确认能力范围内，最省的触发组合是：

  • Trigger：New Issue / New Pull Request（Polling，Free 15 min；trigger 本身 0 task）
  • Action：只接一个 Code 步骤做分析。要真正读代码，需要走 Code by Zapier（1 task/step）内调用 GitHub API——这部分不在 GitHub app action 列表内，属额外步骤
  • 更优方案（实测可行）：GitHub 原生 webhook → Zapier Catch Hook（即时 0 task）→ Code by Zapier（1 task）dispatch GitHub Actions → Actions 内用 SDK 调模型（Beta 免费）。这就是当前生产架构（Zap ID 381096178）

D3. 计费边界——哪些操作不算 task

✅ 明确 0 task

  • Trigger（无论 instant 还是 polling）——轮询再频繁也不扣
  • Filter / Paths
  • Formatter / Delay / Looping（步骤本身）
  • Digest / Storage / Zapier Manager
  • Tables / Forms 步骤
  • 失败 / halt / 没跑到的 step
  • Search 设"找不到就停"
  • Agent activity（走独立池，不占 tasks）

❌ 明确算 task

  • 任何 action step（连外部 app 的写操作）
  • error handler 路径里成功跑的 step
  • 整个 Zap run replay——之前成功的 step 会重新扣一遍
  • Sub-Zap：内部每个 action + Call + Return 各 1 task
  • Search 设"找不到也继续" = 1 task
  • Test step 是 live 的，成功就扣 task

D4. 降本技巧（合规、官方鼓励）

  1. 把 Filter 放最前面——Filter 本身 0 task，但能挡掉不满足条件的 trigger，让后续 action 根本不跑。最核心省额度工具。
  2. 用免费内置工具替代付费 action——Formatter、Paths、Delay、Looping、Storage、Tables、Digest 全是 0 task。数据清洗、字符串处理、日期计算、缓存查表全部用这些做。
  3. Search action 设成 "No，not proceed if nothing found"——找不到记录时 0 task；设成 "Yes, continue" 会白扣 1 task。
  4. 用 Code by Zapier 一步合并多步操作——1 次 Code step = 1 task（30s 内）。把 "Find record → Formatter → Update row → Send Slack" 合并成一段代码，3 tasks → 1 task。注意超时会加扣。
  5. 用 Webhook + 自有后端替代多步 Zap——外部系统 POST 到 Zapier Webhook URL = 1 trigger（免费）→ 后端处理 = 1 action task。5 action Zap 从 5 tasks 降到 2 tasks。
  6. 用 Tables / Storage 做缓存避免重复 Find——处理过的记录打 "processed" 标记存 Tables，下次 trigger 先查表，已处理就 Filter 掉。也能防 Agent ↔ Zap 死循环。
  7. Looping 的真相（坑）——Looping 步骤本身 0 task，但 loop 内每个 action 对每个 item 各扣 1 task。100 个 item = 100 tasks。总 task 数不变，只是省 trigger 调用。上限 500 iterations/loop。
  8. Sub-Zap 复用逻辑——内部 action 仍各扣 1 task，不省 task；但省维护成本。注意 Call/Return 本身各扣 1 task——如果 Sub-Zap 里只有 1 个 action，反而比直接写多扣 2 task。
  9. 轮询频率——轮询本身免费，但频率越高越容易在短时间内 fire 更多 action = 更多 task。非实时场景用 Schedule 设成每小时/每天。
  10. AI by Zapier 降本——默认 Advanced = 3 tasks/run，日常简单文本处理切到 Standard（1x），立省 2/3。复杂推理才用 Premium（5x）。能写死 if/then 逻辑的别让 LLM 每次重算。用 BYOK（自带 key）= 1x 倍率。
  11. 关掉 pay-per-task——超额后默认 1.25x 自动扣。在 Billing 关掉，让 run held，等下月重置或手动 upgrade。

G. Chatbot & MCP 简介

G1. Chatbots（Zapier Chatbots）

  • 是什么：嵌入网页的 AI 客服机器人，可连接知识源（文档/网站），能触发 Zap 执行动作
  • 计费：独立订阅 add-on，不占 tasks。Pro $160/年（$13.33/月，5 chatbots）；Advanced $800/年（$66.67/月，20 chatbots，可去 Zapier 标识）
  • 免费试用：创建第一个 Chatbot 自动开 14 天 Advanced 试用
  • GitHub 场景：挂一个 bot 到开源项目 README/文档站，回答"怎么安装""常见 issue"，知识源同步 GitHub Wiki/Docs
  • 与全仓分析的关系：不直接相关。Chatbot 是面向终端用户的问答界面，不是批量代码分析工具

G2. Zapier MCP（Model Context Protocol）

  • 是什么：让 AI 客户端（如 Claude Desktop、Cursor）通过 MCP 协议调用 Zapier 的 9000+ app 工具
  • 计费：每个成功 tool call = 2 tasks（从现有 task 池扣）；失败 call = 0 tasks。比 Zap 的 1 task/action 贵 1 倍
  • 所有计划可用：Free/Pro/Team/Enterprise 均可使用 MCP
  • GitHub 场景：在 Claude Desktop/Cursor 里通过 MCP 调用 Zapier 的 GitHub action（建 Issue、加 label 等），但每次调用 2 tasks 比直接用 GitHub API 贵
  • 与全仓分析的关系：不推荐用于批量代码分析——2 tasks/call 的成本太高，且 MCP 是交互式工具调用，不适合批量异步处理
  • Early Access：从 AI 工具"build a Zap"免费；运行 next-gen Zap 在 Early Access 后按标准 1 task/action 计费
